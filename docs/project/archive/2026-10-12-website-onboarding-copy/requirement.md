# 让新用户理解 SpecTrail 并完成首次使用

## 背景与目标

现有产品介绍站已经发布，但首页优先展示工程文件、流程状态等术语，首次访问者需要自行理解 Skill、工作台与原型管理的关系，以及安装后如何开始使用。用户要求“文案全部让 iclaude 重新组织一下，页面内容的合理性也让他 review 一下。需要让用户容易理解好上手”。

本 Change 只记录这轮内容调整。此前建站和发布没有建立 Change，不补写历史确认或验收记录。

## 范围

由本机 `iclaude` 审阅并重写首页、Skill、工作台、原型管理页面及共用导航、按钮、复制反馈、示例说明。内容调整以真实产品能力为依据，保留现有视觉系统和页面地址；必要时在现有页面内调整章节顺序与行动入口。

这是 small：主要改写一项站点内容职责，不改变产品 API、权限、持久化契约、安装工具或发布流程，预计不到 300 行有效实现代码。共用工作流配置及校验入口为本仓库建立真实的 Change 记录，不修改分发 Skill 规则。

实际安装调查发现，skills@1.7.1 的 Claude Code 单客户端复制模式只生成 `.claude/skills/spec-trail/`，缺少现有脚本约定的 `.agents/skills/spec-trail/`。安装指引改为同时选择 `universal claude-code`，保留现有安装工具和脚本约定，并同步公开 README；在临时 Git 仓库验证两个入口与只读接入检查。

## 行为变化

### MODIFIED `product-introduction/onboarding`

- 首页先说明适用人群、解决的问题和三个模块的区别；帮助读者选择第一步。
- Skill 页面将准备条件、安装、项目接入和第一条任务连成可执行路径，提前解释 Change 与 Specs 等必要术语。
- 工作台说明能查看什么、怎样获得实例入口、连接仓库后会看到什么；不会将介绍站或设计示例写成可登录的在线工作台。
- 原型页面先解释使用场景和演示入口，再说明如何启用；托管与技术命令放在需要时阅读的位置。
- 所有提示词、按钮及反馈清楚说明操作和下一步；不承诺未实现能力、耗时或无法公开访问的服务。

## 方案要点

先保存当前页面截图，交给独立 `iclaude` 会话审阅，并由其改写内容。核对每项建议与仓库 Skill、公开 README、工作台实际能力一致，再运行静态检查和既有浏览器验证，对修改后的内容做第二次 iclaude 复审。使用现有 Cloudflare Pages 工作流验证预览和发布结果，沿用用户已授权的产品站发布范围。

共享工作流用相对链接复用分发 Skill；本机启用仓库维护的提交 hook，在临时仓库实际验证有效状态可提交、错误状态被拒绝。

## 验收标准

1. 四页和共用界面的全部文字经过 iclaude 审阅与组织，保存具体问题、改写及复审结论。
2. 首次访问者能从首页区分“Agent 中推进工作”“浏览器中查看记录”“讨论界面设计”，并找到相应使用入口。
3. 仅使用 Skill 的读者能按安装、接入、第一条任务完成阅读路径；命令与分发 README 一致，复制按钮和提示词可用。
4. 工作台入口与权限前提、原型示例与正式业务的关系说明准确；源码与现有产品事实一致。
5. 四页在桌面和手机可读，本地链接、示例切换、移动导航、键盘操作、无 JavaScript 阅读均通过现有检查；公开预览可访问并显示本次内容。
