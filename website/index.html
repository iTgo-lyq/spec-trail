一项改动会经历什么

从一句目标，到可回看的交付。

在 SpecTrail 里，一次有目标、范围和验收条件的改动叫作一个 Change；已经实现并验证过的当前能力说明叫作 Specs。
改动大小不同，流程有何不同

  1. 01

    对齐目标

    你描述想做的改动。Agent 先查看代码和已有记录，整理目标、范围和验收条件，估计改动大小，请你确认方向。

  2. 02

    方案与任务

    小改动直接写明方案要点和任务；较大的改动先写技术方案和计划，由你确认后再动手。

  3. 03

    实现并验证

    Agent 逐个任务实现并运行验证，把代码、进度和验证结果一起提交推送。

  4. 04

    验收与归档

    小改动由 Agent 对照验收条件自查；较大的改动等你验收。之后更新 Specs，把这次 Change 归档保存。

开始前常见问题

先装 Skill，
其余按需添加。

只安装 Skill 可以使用吗？

可以。Skill 不依赖工作台或原型管理。所有记录都是仓库里的 Markdown 和 JSON 文件，在编辑器或 GitHub 上就能直接阅读。

支持哪些 Agent？

本站提供 Codex 和 Claude Code 的安装命令；也可以为其他支持 Agent Skills、能运行命令并操作 Git 的客户端安装。Skill 指令目前使用中文，适用于单个 Git 仓库及同仓库的分支和 worktree。

小改动也要写很多文档吗？

不会。问答、讨论、只读调查，以及不改变行为的拼写、注释、格式修正，都不需要建立 Change。小改动只写一份需求（含方案要点和任务）；改动越大，才需要技术方案、计划和评审记录。

Agent 会自己提交、合入代码吗？

Agent 会在这项改动自己的分支上提交并推送进度。合入 main、创建 PR 或发布都按你的授权进行：归档后，Agent 会问你直接合入、发起 PR，还是暂不处理。

Agent 会替我验收吗？

只有小改动默认由 Agent 对照验收条件自验收，并在记录中注明是自验收；你也可以要求人工验收。中等及以上的改动必须等你实际验收，测试通过不等于验收。

工作台会修改我的仓库吗？

不会。OpenFolio 只读取已经提交推送的记录。需求、任务和进度由 Agent 在仓库中维护，推送后刷新工作台即可看到。

原型会用到真实数据吗？可以公开分享吗？

原型使用示例数据演示页面和组件交互，不连接真实业务服务。发布后的原型地址通常可以公开访问，因此只放适合公开的演示内容；工程记录则按各自的仓库权限读取。
