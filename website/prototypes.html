CURRENT当前清单

CHANGE固定版本

每个 Change 保留自己的版本、地址、源码提交和设备信息，归档后继续可回看。

修改当前原型不会替换旧 Change 的交付版本。页面可声明桌面、iPad 和手机设备；组件可声明自己的预览尺寸。

可选接入

告诉 Agent，你需要设计原型。

先完成 SpecTrail 项目接入，再向 Agent 说明原型目标：

使用 $spec-trail，为当前项目启用原型管理。沿用现有 UI 规范，制作订单导出页面的交互原型，使用示例数据，并将固定版本关联到本次 Change。

Agent 会核对项目的原型接入选择，初始化或沿用原型包，整理设计规范，并确定使用 OpenFolio、自建托管还是 Git 兜底。你也可以明确告诉 Agent 现有托管地址和发布约定。

三种交付方式

选择适合项目的托管。

方式适用情况如何交付
OpenFolio 内置托管已经有 OpenFolio 实例通过管理员提供的上传入口发布静态产物，获得固定地址
自建托管已有静态站或对象存储项目适配器上传并验证公开产物，返回固定版本引用；本仓库示例使用 Cloudflare R2
Git 单 HTML希望直接在 Git 中保留原型生成资源内联的单个 HTML，登记到当前清单，并复制独立快照到 Change

多文件静态产物由项目自己构建。固定版本的字节与地址需要持续保留，历史 Change 才能回看同一份设计。

从源码到固定引用

构建、发布、登记，再提交。

  1. 在原型包中维护页面、组件、mock 和设计规范，提交源码。
  2. 构建静态产物，为每个入口声明设备或尺寸。
  3. 通过选定的托管方式发布完整产物，并验证可访问的版本。
  4. 登记到当前清单和对应 Change，提交并推送引用。

Agent 使用原型子模块提供的 prepare、upload / register 与 validate 命令完成交付。具体命令和契约见 原型模块文档。

发布成功后，才更新引用。

上传失败保留原引用；已经交付的版本保持不变。归档时保留对应记录与源码，托管服务负责持续保存外部产物。

设计讨论与验收

打开对应版本，验证关键交互。

通过工作台浏览当前原型，或从 Change 打开关联版本。选择需要的设备或组件尺寸，核对布局、状态切换和关键操作；验证结果随 Change 记录。

原型在浏览器沙箱中运行，使用示例数据演示交互。已发布版本可以公开分享，适合让协作者直接查看页面与设计状态。
