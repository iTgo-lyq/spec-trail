OpenFolio 是单独部署的只读网页工作台。用你自己的 GitHub token 连接后，它会列出你有权读取、已接入 SpecTrail 的仓库，展示当前能力说明（Specs）、各分支上的改动（Changes）和关联原型。它是可选的：向团队管理员获取实例地址后即可开始；只用 Skill 也能完整工作。

获取入口与连接

先拿到实例地址，再连接你的 GitHub。

连接在团队的 OpenFolio 实例中进行。

本站是介绍页。OpenFolio 目前没有面向所有访客的公共实例，请打开团队部署的工作台地址，完成下面的步骤。

  1. 向团队中维护 OpenFolio 的管理员索取工作台地址。团队还没有实例时，可以请有源码权限的维护者按部署说明搭建；在此之前，记录可以直接在仓库中阅读。
  2. 在 GitHub 创建一个 token，只为需要查看的仓库授予读取内容的权限（细粒度 token 选择 Contents: Read-only）。组织仓库可能需要组织管理员批准或 SSO 授权。
  3. 打开工作台地址，选择“连接 GitHub”，按页面提示提供 token。工作台会列出这个 token 能读取、且已接入 SpecTrail 的仓库。
  4. 选择仓库开始阅读。Agent 推送新记录后，刷新页面即可看到。

目标仓库不在列表中时，可以输入它的 GitHub HTTPS 地址手动检查，并回到第 2 步核对 token 的仓库权限。

与 Skill 如何配合

改记录用 Agent，看记录用工作台。

OpenFolio 只读取中心仓库里已经提交并推送的记录，不会修改需求、任务或进度。本地尚未提交或推送的内容不会出现在工作台。

你想做什么在哪里做
新建或推进改动，修改需求与任务在 Agent 对话中使用 SpecTrail Skill，提交并推送
查看文档和当前进展在 OpenFolio 中选择仓库和分支，刷新页面
制作或更新设计原型在 Agent 中使用原型管理，发布并登记后推送
回看已完成的改动在 OpenFolio 中打开已归档的 Change，查看验收依据和对应版本

Specs 来自所选分支；Changes 汇总各个已推送分支，每个 Change 以它自己的分支为准；项目当前原型来自默认分支上的原型清单。

访问权限与分享

工程内容按仓库权限读取，原型可以公开分享。

工程内容

复制阅读链接，可以稍后回到同一位置，也可以发给协作者。协作者在同一个 OpenFolio 实例中用自己的 GitHub token 连接后打开链接；能看到哪些记录，取决于这个 token 对仓库的读取权限。

原型链接

已发布的原型是静态页面，地址通常可以公开访问，适合直接发给协作者预览。因此原型只应包含示例数据和适合公开的设计内容。旧版本能否继续打开，取决于托管服务是否持续保存该版本。

进阶 · 部署实例

由有源码权限的管理员部署。

拥有 OpenFolio 源码访问权限的维护者，按源码中的 README 完成部署、配置、备份和升级（源码目前未公开）。下面的摘要帮助你评估所需环境。

查看构建与启动步骤摘要（需要源码访问权限）

需要 Node.js 24、Git 和持久磁盘；Git 原型截图功能还需要 Playwright Chromium 和可用的系统沙箱。在源码目录中执行：

OpenFolio 构建与启动
npm ci
npx playwright install --with-deps chromium
npm run build
npm start
启动后在本机打开：http://127.0.0.1:10681

服务默认只监听本机，远程访问通过 HTTPS 反向代理提供。它以单进程、单实例运行，需要持久数据目录；具体配置以源码 README 为准。
